One X-ray Example — Start to Finish

Trace one training example from JSON → Alpaca text → tokens → combined input

1 You Write One JSON Example

One chest X-ray image + one question + one doctor's answer. That's it.

{
  "image": "chest_xray_001.jpg",
  "instruction": "What does this chest X-ray show?",
  "output": "Bilateral pneumonia in the right lower lobe."
}

3 fields. Same as text FT, just with "image" added.

↓

2 Two Paths Split Here

The "image" field goes to the vision encoder. The "instruction" and "output" go through Alpaca formatting.

🖼️ Path A: Image

"chest_xray_001.jpg"
↓
CLIP-ViT-L (304M params, FROZEN)
↓
197 visual tokens
each = 1024 numbers
↓
Project to 4096-dim

📝 Path B: Text (Alpaca)

format_instruction()
↓
One long string
↓
Tokenizer
↓
Text token IDs
each = 4096-dim (embedding)

Path A and Path B run COMPLETELY independently. The image never touches format_instruction(). The text never goes through CLIP-ViT-L. They only meet at the LLM input.
↓

3 Path B: Text → Alpaca String → Token IDs

The instruction and output are formatted using the SAME Alpaca template as text fine-tuning.

format_instruction() produces this exact string:

Below is an instruction. Write a response.

### Instruction:
What does this chest X-ray show?

### Response:
Bilateral pneumonia in the right lower lobe.

Then tokenized (simplified — first few tokens):

[1, 464, 8522, 318, 247, 3749, ...  // "Below", "is", "an", "instruction"...]
...more tokens...
[..., 318, 464, 8522, 318, 247, ...  // "Bilateral", "pneumonia"...]

Each integer → looked up in embedding table → 4096-dim vector

↓

4 What the LLM Actually Receives

Path A's 197 visual tokens are placed at the front. Path B's text tokens follow. The LLM sees one flat list.

v₁
v₂
v₃
···
v₁₉₇
t₁
t₂
t₃
···
tₙ

■ 197 visual tokens + ■ ~300 text tokens = ~500 total tokens, each 4096-dim

🧠 THIS is what the Transformer processes:

Token 1: [0.12, -0.34, 0.78, ...] ← image patch (from CLIP-ViT-L)
Token 2: [0.45, 0.21, -0.11, ...] ← image patch
···
Token 198: [-0.28, 0.55, 0.31, ...] ← "Below" (from embedding table)
Token 199: [0.63, -0.17, 0.89, ...] ← "is" (from embedding table)

Every token is 4096 numbers. The LLM processes them ALL through the same Q/K/V attention. It has no idea which tokens came from the image and which came from the text.

5 The LLM Generates the Answer

Same as text-only. It reads the 500 tokens, processes through 32 Transformer layers (with LoRA on Q+V), and predicts the next word — which should be the medical answer it learned during training.

Training label (from JSON output): "Bilateral pneumonia in the right lower lobe." The LLM's job: See 500 tokens → predict "Bilateral" → predict "pneumonia" → predict "in" → ... Each prediction compared to the label → loss → gradient → update LoRA (B and A)
