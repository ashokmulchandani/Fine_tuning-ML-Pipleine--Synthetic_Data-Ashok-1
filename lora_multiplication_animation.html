How LoRA Actually Computes

Q_output = W_q·x (frozen) + B_q·(A_q·x) (tiny side path). 4 steps. Same for V.

Step 1/4
🧠 Why this matters: B×A is NEVER computed as a full 4096×4096 matrix. Always two cheap steps: A·x (32K ops) then B·(A·x) (32K ops). Total LoRA overhead = 0.39%. At inference, merge B×A into W → ZERO overhead.

Where B×A×x Happens — Across 32 Layers

The Big Picture: 2 Adapters Per Layer × 32 Layers = 64 Independent B×A Pairs

The input flows through 32 transformer layers. At every layer, Q and V each have their OWN B×A adapter (4-step computation from above). K and O have no adapters.

Layer 1Q✅KV✅O+ B¹_q×A¹_q + B¹_v×A¹_v
Layer 2Q✅KV✅+ B²_q×A²_q + B²_v×A²_v
⋮
Layer 32Q✅KV✅O+ B³²_q×A³²_q + B³²_v×A³²_v

Each adapter is INDEPENDENT. Layer 3 adjusts grammar. Layer 28 adjusts style. They learn different things.

The Two Rules of LoRA Forward Pass

Rule 1: A·x first (cheap, r dimensions) → B·(A·x) cheap. B×A NEVER computed as full matrix. Two cheap steps.
Rule 2: Q in layer 3 ≠ Q in layer 15. 64 independent B×A pairs. Each learns what THAT layer needs.
Bonus: At inference, merge B×A into W → zero overhead. Same as original model speed.
