🔑 Tokenizer = Dictionary Lookup. It has a fixed vocabulary of 32,000 subwords. "Metformin" is not in the vocabulary (too rare), so it splits into "Met" + "formin" (both ARE in the vocab). Like breaking an unknown word into syllables you DO know.

Step 2: Embedding — Integer ID → 4096-Dimensional Vector

Each token ID looks up its vector in the Embedding Matrix (32,000 rows × 4096 columns = 131M params). YES — every single word has its own 4096-number vector.

🧠 The Embedding Matrix = A Giant Lookup Table.
  Token 464 → Row 464 of the matrix → 4096 numbers
  Token 8522 → Row 8522 → 4096 numbers
  Every token gets its OWN vector. 'Met' and 'formin' have different vectors because they mean different things.

Is this the same as Q/K/V attention? NO. Embedding is the FIRST step (text → vector). Q/K/V attention happens AFTER embedding (vector → context-aware vector). Two different things.
↓

🖼️ Image Tokenization — How an Image Becomes Tokens

224×224 pixels → 14×14 patches → 197 visual tokens → combined with text → LLM processes everything together

224×224 = 50,176 pixels (simplified X-ray pattern)

Step 1: Split into 14×14 Patches (16×16 pixels each)

14×14 = 196 patches. Each = 16×16 = 256 numbers. Highlighted: one patch.

Zoomed patch: 16×16 = 256 pixel values. Dark=bone, light=lung.

Step 2: CLIP-ViT-L Encodes → 1024-dim Vectors

196 patches + 1 [CLS] → CLIP-ViT-L (304M, FROZEN) → 197 tokens, each 1024-dimensional.

197 visual tokens (each colored row = one 1024-dim vector). The LLM needs 4096-dim...

Step 3: Project to LLM Space — 1024 → 4096

A linear layer (1024×4096 = 4.2M params, FROZEN) maps each visual token to 4096-dim — the exact size the LLM expects.

Step 4: Combine Visual + Text → One Input

197 visual tokens are prepended to text tokens (variable, ~300) = 512 total tokens, each 4096-dim. The LLM processes them identically.

■ 197 visual (38.5%) ■ 315 text (61.5%) = 512 tokens total

After This: Visual + Text Tokens Go Through Transformer ×32 Together

Once combined into 512×4096, the Transformer processes visual and text tokens identically. Same Q/K/V attention. Same feed-forward. Same LoRA on Q+V. The model doesn't know which token came from where.

Vision-Language models (LLaVA, GPT-4V) process images the same way — by converting them into tokens. But the tokenizer is different.

Step 1: Split Image into Patches

A 224×224 pixel image is divided into 14×14 = 196 patches. Each patch = 16×16 pixels. Just like text is split into words, an image is split into patches.

TextImage
"Metformin" → "Met" + "formin" (2 subwords)224×224 image → 196 patches (14×14 grid)
Tokenizer splits by vocabulary (32K words)ViT splits by grid (fixed 16×16 pixel squares)
Output: integer IDs [464, 8522]Output: patch vectors [p₁, p₂, ..., p₁₉₆]

Step 2: CLIP-ViT Encodes Each Patch

Each 16×16 patch (256 pixels) is flattened into a vector, then projected through CLIP-ViT-L (304M params). The output: each patch becomes a 1024-dim vector. Plus one special [CLS] token = 197 visual tokens total.

# CLIP-ViT-L/14 processes a 224×224 image: 224×224 pixels → 14×14 grid of 16×16 patches = 196 patches + 1 [CLS] token (summary of whole image) = 197 visual tokens, each 1024-dimensional # These 197 tokens then go through a projection layer: 1024-dim (vision space) → 4096-dim (LLM space) = 197 tokens × 4096-dim → matched to LLM input size!

Step 3: Combine Visual + Text Tokens

The 197 visual tokens are PREPENDED to the text tokens. The LLM sees them as one long sequence:

🧠 Key insight: The LLM doesn't know visual tokens from text tokens. It sees 512 vectors of 4096 numbers and processes them identically. The visual tokens carry "what's in this image" as numerical patterns. The text asks the question. The Transformer generates the answer — exactly like text-only input.
