3. Which Statistical Test for Which Data Type?

Evidently auto-selects the right test per feature. You don't pick — it detects the data type (text, number, category) and applies the correct math.

Data TypeTest UsedWhat It Checks
Text ROC-AUC Domain Classifier Can a tiny ML model tell training text apart from production text? If yes (ROC-AUC > 0.7) -> the distributions are different -> DRIFT. Evidently trains a TF-IDF + LogisticRegression classifier internally.
Numeric Kolmogorov-Smirnov (KS) Test Are these two samples from the same underlying distribution? Checks if the entire shape of the distribution changed — not just the average, but variance, tails, everything.
Categorical Chi-Squared Test Are the category proportions the same? Compares observed frequencies vs expected frequencies. If the proportions changed significantly -> drift.
Chi-squared formula in plain English:
chi2 = sum of (observed_count - expected_count)^2 / expected_count

Big chi2 -> observed frequencies are very different from expected -> drift.
Small chi2 -> observed and expected are similar -> no drift.

4. p-value — How Confident Are We It's Real Drift?

The p-value answers one question: "Could this difference just be random noise?" Lower p-value = more confident it's real.

p = 0.001
"99.9% sure
this is real drift"
DEFINITELY DRIFT
p = 0.05
"95% sure
this is real"
BORDERLINE
p = 0.50
"50/50 — could
just be random"
NOT REAL DRIFT
p less than 0.05 is the standard scientific threshold. It means: "There's less than a 5% chance this difference is random noise." If p less than 0.05 AND drift score greater than 0.5, you retrain. If p greater than 0.05, the difference might be random — don't act on it yet.

5. How to Read the Drift Score

Drift ScoreMeaningAction
0.0 - 0.3No drift — model is fine. Distribution matches training.Keep monitoring daily
0.3 - 0.5Mild drift — some new topics appearing. Monitor closely.Check weekly. Prepare new data.
0.5+DRIFT DETECTED. Users asking about topics you never trained on.Collect new Q&A -> retrain with dvc repro
Drift score = percentage of features that drifted. A score of 0.62 means 62% of measurable features show statistically significant difference from training. That's bad — more than half the input data has changed.

Drift = the DISTRIBUTION of questions changed. It's not that users ask one new question. It's that the PATTERN of questions shifted — from "mostly medical" to "50% medical + 26% web dev + 24% cooking." The model was never trained on web dev or cooking. 7. The Complete Data Quality Stack

No single tool catches everything. Each layer catches failures the others miss.

LayerToolWhat It ChecksWhen
Schema Pandera Are all columns present? Any nulls? Correct types? Empty strings? BEFORE training
Behavior pytest Does model know basic facts (MFT)? Robust to paraphrasing (INV)? Refuse harm (DIR)? AFTER training
Trends DVC Is the dataset growing? Shrinking? New nulls appearing? Vocabulary changing? EVERY dvc repro
Drift Evidently AI Are users asking about NEW topics? Has the distribution shifted? Response quality dropping? DAILY (6am UTC)
Each layer feeds the next. Pandera catches bad data -> DVC shows trends over time -> Evidently catches distribution shifts -> pytest validates the model still works. All four together = complete quality coverage. None replaces the others.
