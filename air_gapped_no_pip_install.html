Air-Gapped Install — No PIP, No Internet

How to move Python libraries manually onto a computer with no internet connection

1 The File Format: .whl (Wheel)

Python libraries ship as .whl files — ZIP archives containing the code. Every pip install you've ever run downloaded one of these.

Real Wheel FileTypeWorks On

2 The 3-Step Transfer Process

Download on the ONLINE machine

Use pip download — it grabs every .whl including dependencies, into one folder.

Copy the folder to the OFFLINE machine

USB drive, external HDD, CD, sneakernet — whatever works. The offline_packages/ folder is self-contained.

Install from the folder on the OFFLINE machine

pip install --no-index --find-links=offline_packages/ ... — no internet needed.

3 Step 1 — Download Everything on the Online Machine

Run these commands on a machine WITH internet access. This does NOT install anything — it only downloads .whl files.

# Create a folder to hold all .whl files mkdir offline_packages # Download pytest + ALL its dependencies (pluggy, iniconfig, ...) pip download pytest -d offline_packages # Download pandera + ALL its dependencies (pandas, numpy, typing_extensions, ...) pip download pandera -d offline_packages # Or download EVERYTHING in one command: pip download pytest pandera pandas numpy -d offline_packages # Check what you got: ls offline_packages/ # pytest-8.3.4-py3-none-any.whl # pandera-0.22.2-py3-none-any.whl # pluggy-1.5.0-py3-none-any.whl # iniconfig-2.0.0-py3-none-any.whl # packaging-24.1-py3-none-any.whl # pandas-2.2.3-cp312-cp312-win_amd64.whl # numpy-2.1.3-cp312-cp312-win_amd64.whl # ... ~10 more files
💡 Key: pip download resolves the full dependency tree. pytest needs pluggy, iniconfig, and packaging. pandera needs pandas, numpy, and typing_extensions. One command grabs it all.

4 Step 2 — Transfer to the Air-Gapped Machine

Copy the entire offline_packages/ folder to the offline computer. Any method works:

MethodGood For
USB flash driveMost common — folders up to 100 MB
External HDD/SSDLarge ML libraries (PyTorch ~2 GB)
Internal network shareLab computers on same LAN (not internet)
CD/DVDHigh-security environments that block USB
⚠️ Important: The online and offline machines must have the same Python version and the same operating system if any package contains compiled C code (pandas, numpy, PyTorch). Pure Python py3-none-any wheels work anywhere.

5 Step 3 — Install on the Air-Gapped Machine

On the offline computer, point pip at your folder instead of PyPI:

# Install from local folder — ZERO internet required pip install --no-index --find-links=offline_packages/ pytest pandera # --no-index = "Don't look at PyPI (the internet)" # --find-links = "Look here instead" (your folder of .whl files)
✅ That's it. pip reads the .whl files from your folder, resolves dependencies locally, and installs everything. No internet. No PyPI. No network at all.

6 Different Platforms — Cross-OS Download

If your online machine is Windows but the air-gapped machine is Linux, you must download wheels for the target platform:

# Download wheels for LINUX from a WINDOWS machine pip download pandera -d offline_packages \ --platform manylinux2014_x86_64 \ --python-version 3.12 \ --only-binary=:all: # Download wheels for WINDOWS from a LINUX machine pip download pandera -d offline_packages \ --platform win_amd64 \ --python-version 3.12 \ --only-binary=:all:
Target OS--platform flag
Windows 64-bit--platform win_amd64
Linux 64-bit (x86)--platform manylinux2014_x86_64
macOS Intel--platform macosx_10_9_x86_64
macOS Apple Silicon (M1/M2/M3)--platform macosx_11_0_arm64

8 One-Liner Cheat Sheet

# ┌─── ONLINE MACHINE (with internet) ───┐ mkdir offline_packages pip download pytest pandera -d offline_packages # Copy offline_packages/ to USB drive # ┌─── AIR-GAPPED MACHINE (no internet) ───┐ # Copy offline_packages/ from USB drive pip install --no-index --find-links=offline_packages/ pytest pandera # ┌─── VERIFY ───┐ python -c "import pytest; import pandera; print('✅ Ready')"

9 Common Mistakes

MistakeWhat HappensFix
Wrong Python versionWheel has cp312 but target has Python 3.11Use --python-version 3.11 when downloading
Wrong platformDownloaded win_amd64 but target is LinuxUse --platform manylinux2014_x86_64
Forgot dependenciesInstalled pytest but not pluggy → import failsAlways pip download (not manual .whl selection)
Used pip install instead of pip downloadInstalled on online machine, nothing to transferpip download only saves files, doesn't install
Mixed .whl and .tar.gz in folderSource distributions need compilation (no compiler on offline)Add --only-binary=:all: to skip source dists

10 Bonus: Entire requirements.txt at Once

# 1. Export your current environment (online machine) pip freeze > requirements.txt # 2. Download ALL wheels for the entire environment pip download -r requirements.txt -d offline_packages # 3. On the air-gapped machine, install everything pip install --no-index --find-links=offline_packages/ -r requirements.txt
🔐 Pro tip: Many air-gapped environments also require a security scan. Your security team can scan the offline_packages/ folder once (whitelist those hashes), then you never need to re-scan — you're reusing the same verified .whl files.
