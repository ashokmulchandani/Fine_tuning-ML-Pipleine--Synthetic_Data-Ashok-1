How an Image Becomes Tokens

224×224 pixels → 14×14 patches → 197 visual tokens → combined with text → LLM processes everything together

1 The Image — 224×224 Pixels

This is what the model "sees." A chest X-ray, 224 pixels wide × 224 pixels tall. Each pixel has a value (0=black, 255=white).

224×224 = 50,176 pixels (simplified X-ray pattern)

↓

2 Split into 14×14 Patches (16×16 pixels each)

The image is divided into a 14×14 grid. Each cell = 16×16 pixels = one patch. 224 ÷ 16 = 14. Result: 196 patches.

Each patch = 16×16 = 256 pixels. Flattened into 256 numbers.
One patch shown zoomed (4×4 subset to fit): dark=bone, light=lung, white=background.

One patch = 16×16 = 256 pixels. Each pixel value (0=black, 1=white) becomes one number in the vector.

↓

3 CLIP-ViT-L Encodes Each Patch → 1024-dim Vector

All 196 patches go through CLIP-ViT-L (304M params, frozen). Each 256-number patch becomes a 1024-number vector. Plus 1 special [CLS] summary token = 197 tokens.

4 Project to LLM Space — 1024 → 4096

🧠 The Projection Layer = "Language Translator" for Images.
CLIP-ViT outputs in "vision language" (1024-dim). The LLM speaks "text language" (4096-dim). This layer translates between them. Once translated, the LLM can process visual tokens exactly like it processes words.
↓

5 Combine Visual + Text → One Input

The 197 visual tokens are prepended to the text tokens. The LLM sees one flat sequence of 512 tokens, each 4096-dim. It doesn't know which came from the image.

■ 197 visual tokens (38.5%)   ■ 315 text tokens (61.5%)   = 512 total, each 4096-dim
