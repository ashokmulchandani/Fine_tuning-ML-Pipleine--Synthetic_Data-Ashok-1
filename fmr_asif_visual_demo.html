How FMR Works

Pretrained models produce features where some dimensions dominate (high magnitude) regardless of whether they're useful. FMR adds an entropy-maximization loss to equalize all feature magnitudes.

// FMR Loss — surprisingly simple
features = backbone(image) // extract features
p = softmax(features) // normalize → probability-like
H = -sum(p * log(p)) // compute entropy
λ = (Hmax - H) / (Hmax - Hinit) // dynamic weight
Ltotal = LCE - λ * H // maximize entropy = minimize -H
Biased features (dominate) Equalized features Hmax target

Training Curves: Entropy, Loss & λ Over Time LIVE

As FMR equalizes feature magnitudes: Entropy H ↗ rises toward Hmax, λ ↘ auto-decays, |FMR Loss| ↘ fades, and Total Loss ↘ converges.

Entropy H (→ Hmax) Dynamic λ (auto-decays) |FMR Loss| = |−λ·H| Total Loss = LCE − λ·H

Gradient Tug-of-War: Why Useful Features Survive KEY INSIGHT

Each feature experiences two opposing gradients: ▸ CE Loss gradient = "stay strong, you help classification!" (only for useful features)   ▸ FMR gradient = "move toward the uniform target!" (for ALL features). If CE doesn't fight back → FMR wins → feature suppressed. If CE fights back → stalemate → feature survives.

∂LCE/∂f — CE gradient (classification needs this) ∂LFMR/∂f — FMR gradient (pushes toward uniform) Net gradient = CE + FMR ═══ Uniform target

Gradient Flow & Dynamic Reversal (DGR)

The DGR layer passes features through unchanged on the forward pass but reverses and scales gradients during backpropagation. λ auto-adjusts: stronger reversal when the identifier is doing too well.

// DGR Algorithm — no manual λ tuning!
L̂id = log(Nc) // baseline: max-entropy identification
λ = 1.0
while training:
  Lid = identify(features) // how well can we ID samples?
  backprop with λ * gradient_reversal
  λ = (Lid - L̂id) / L̂id // auto-adjust

Section 01

The Problem: Too Few Labeled Images, Too Many Subtle Differences

Fine-grained visual recognition (FGVR) means telling apart nearly identical things — like 200 species of birds that all look the same to an untrained eye. You can't gather millions of labeled images for every bird species. So you transfer-learn from a model pretrained on ImageNet (1.2M general images).

❌ THE TRAP

The pretrained model was trained on different data. It learned that "green background = outdoors" and "blue = sky." These features are LOUD (high magnitude) but useless for telling bird species apart. With only a few training images, the classifier latches onto these loud-but-irrelevant features and overfits.

✅ THE FIX (FMR)

FMR adds a penalty that says: "All features must have equal prominence." Loud background-detector features get pushed DOWN. Quiet beak-shape features get a chance to be HEARD. The classifier is forced to use features that actually generalize — like beak curvature and wing patterns.

Section 02

What Are "Features"? NOT Pixels!

When the paper says "features," they mean the 2048-dimensional output of a pretrained CNN's penultimate layer — NOT raw RGB pixel values. Each of the 2048 numbers is an abstract learned representation detecting something: a shape, texture, pattern, or concept.

Input Image (224×224×3)
 ↓
Pretrained ResNet-50 Backbone (frozen or fine-tuned)
 ↓
Feature Vector f ∈ ℝ²⁰⁴⁸ ← THIS is what "features" means
e.g., [0.91, 0.12, 0.67, ..., 0.04]
 ↓
Linear Classifier W (2048 → 200 classes) ← the ONLY thing we train
 ↓
Prediction: "Indigo Bunting"
Section 03

The Core Insight: Feature Magnitude Bias

Let's say f₁ = 0.91 and f₂ = 0.03. The classifier sees f₁ is 3,000% larger than f₂. If f₁ happens to detect "green background" and green correlates with a bird class in your tiny training set, the classifier will rely heavily on f₁ — even though beak shape (f₂ = 0.03, quiet) is what actually matters.

💡 Key Realization: The pretrained model baked in biases about which visual patterns are "important" based on its original ImageNet training. These biases are encoded as uneven feature magnitudes. FMR undoes this bias by forcing all feature dimensions toward equal prominence.
Section 03B

📖 Key Definitions — Entropy, Feature Dominance & Why They Matter

📉 LOW Entropy = Feature Dominance (BAD)

Some features are loud (high magnitude), others are quiet (near zero). A few loud features dominate the classifier's decisions — the model ignores 95% of what it sees.

f = [0.91, 0.87, 0.83, 0.05, 0.03, 0.02, ...]
H = 1.8  (far below Hmax = 3.40)
→ 3 features control everything

Real meaning: The pretrained model shouts "BLUE SKY! GREEN GRASS!" so loudly that the whisper "curved beak..." is never heard by the classifier.

📈 HIGH Entropy = Uniform Features (GOOD)

All features have similar magnitude — no single feature shouts over the others. The classifier considers all features equally and picks the ones that actually help.

f = [0.52, 0.49, 0.51, 0.48, 0.50, 0.47, ...]
H = 3.35  (near Hmax = 3.40)
→ All 2048 features get a fair chance

Real meaning: "Blue sky" and "curved beak" now speak at equal volume. The classifier's cross-entropy loss naturally amplifies beak curvature (it helps classify) and ignores sky (it doesn't).

Term Definition Why It Matters
Entropy H H = −Σ p_i × log(p_i) where p = softmax(f)
Measures how evenly feature magnitudes are spread out.		 Low H = biased features (bad).
High H = uniform features (good).
FMR maximizes H.
Hmax Hmax = log(D) where D = number of feature dimensions (e.g., log(2048) ≈ 7.62) The theoretical ceiling. Reached when ALL D features have exactly equal magnitude. The target FMR aims for.
Softmax(f) p_i = e^(f_i) / Σ e^(f_j)
Converts raw feature values into a probability distribution (all p_i ≥ 0, Σ p_i = 1)		 Entropy is only defined for probability distributions. Softmax normalizes features so we can measure their uniformity.
Feature Dominance When a few feature dimensions have much larger magnitudes than others, controlling the classifier's output This is FMR's enemy. Dominant features may be irrelevant (background detectors). FMR breaks their dominance.
Dynamic λ λ = (Hmax − H) / (Hmax − Hinit) Large when H is low (features very biased → push hard).
Small when H is high (features nearly uniform → ease off).
Auto-adjusts — no tuning needed.
🧠 Intuition: Entropy is like a fairness meter for features. Low entropy = "3 features are shouting, 2045 are whispering — unfair!" High entropy = "everyone speaks at equal volume — fair!" FMR's job is to take the unfair pretrained feature distribution and make it fair. Once fair, the classifier (through CE loss) naturally discovers which features actually help classification — without being bullied by the loud ones.
Section 04

The Formula — Every Term Decoded

Ltotal = LCE − λ · H
Ltotal Total training loss — what the optimizer minimizes The sum of two competing objectives
LCE Cross-Entropy Loss — how wrong is the prediction? Standard classification loss: −Σ y_true × log(ŷ)
λ Dynamic weight — how hard should FMR push right now? λ = (Hmax − H) / (Hmax − Hinit) — auto-decays
H Entropy of softmax-normalized features H = −Σ p_i × log(p_i) — measures "uniformity"
−λ·H FMR penalty term Negative because we MAXIMIZE entropy (minimize −H)
🔑 Why "−λ·H" not "+λ·(−H)"? They are mathematically identical. The paper frames it as "minimize LCE + λ·(−H)" — adding a penalty for LOW entropy. The code writes "LCE − λ·H" because it's cleaner. Both mean: penalize the model when feature magnitudes are uneven.
🧾 The COMPLETE Training Objective (All Three Terms)
Ltotal = LCE + λW·ΣW² − λ·H(softmax(f))

 │     │           │
 │     │           └─ FMR (this paper's contribution)
 │     │              Equalizes feature magnitudes f
 │     │              λ = dynamic — auto-decays as H→Hmax
 │     │
 │     └─ Weight Decay (standard L2)
 │        Prevents classifier weights W from exploding
 │        Pulls ALL W toward zero (irrelevant ones die, useful ones resist via CE)
 │
 └─ Cross-Entropy (classification)
    "Am I predicting the right bird species?"
💡 The Weight Table shows only the W Decay term acting on a single classifier weight W. FMR operates on the feature vector f (not shown in the weight table). Both run simultaneously during every training step. Weight decay quietly pulls unused W → 0. FMR loudly pushes biased f → uniform. CE loss ties it all together by fighting for features that actually help classification.
Section 05

Walked Example: "Bird in a Blue Sky" — Where the Push Back Lives

We're classifying an Indigo Bunting (true label). The image shows the bird perched on a branch against a bright blue sky. Two features compete for the classifier's attention.

🔴 SCENARIO A — Irrelevant Feature: "Blue Sky Detector" (fsky = 0.91)

This feature fires strongly whenever the photo has blue sky. In ImageNet pretraining, many bird photos had blue skies — so the model learned to make this feature LOUD. But sky color tells you nothing about which bird species this is. Indigo Buntings and Lazuli Buntings both appear under blue skies.

Step 1 — Classifier's relationship to fsky:
  The classifier learned: "Blue sky appears in ALL bird classes equally"
  → Windigo,sky ≈ 0   Wlazuli,sky ≈ 0   Wany,sky ≈ 0
  → Every class weight for this feature is near zero

Step 2 — CE gradient:
  ∂LCE/∂fsky = (0.7 − 0) × 0.01 = 0.007 ≈ 0
  The CE loss says: "I don't care about sky. Doesn't help me classify."
  CE is SILENT — no opposing force

Step 3 — FMR gradient:
  ∂(−λ·H)/∂fsky = −0.7 × (0.91 − 0.5) × 0.8 = −0.23
  FMR says: "You're 0.41 above the uniform target. Come DOWN."

Step 4 — Net:
  ∂Ltotal/∂fsky = 0.007 + (−0.23) = −0.22
  → fsky drops toward 0.69 this step
  → After many steps: fsky ≈ 0.5 (uniform target)   ✓ SUPPRESSED
🟢 SCENARIO B — Useful Feature: "Beak Curvature Detector" (fbeak = 0.12)

This feature detects curved, conical beaks. In ImageNet pretraining, "has beak = bird" was all that mattered — the fine shape was irrelevant, so this feature stayed QUIET. But for our task, Indigo Buntings have subtly thicker, more curved beaks than Lazuli Buntings. This quiet feature is actually the key.

Step 1 — Classifier's relationship to fbeak:
  The classifier learned: "Curved thick beak = Indigo Bunting!"
  → Windigo,beak = +2.3   (large positive weight)
  → Wlazuli,beak = −1.8   (Lazuli has thinner beak → negative)

Step 2 — CE gradient:
  Model is moderately wrong: predicted 70% Lazuli, but it's actually Indigo
  ŷindigo = 0.3,   yindigo = 1.0
  ∂LCE/∂fbeak = (0.3 − 1.0) × 2.3 = −1.61
  The CE loss says: "You UNDER-used this feature! Make it STRONGER!"
  CE FIGHTS BACK HARD — negative sign means "increase fbeak"

Step 3 — FMR gradient:
  ∂(−λ·H)/∂fbeak = −0.7 × (0.12 − 0.5) × 0.8 = +0.21
  FMR says: "You're below target. Come UP toward uniform." ← actually helps!

Step 4 — Net:
  ∂Ltotal/∂fbeak = −1.61 + 0.21 = −1.40
  → fbeak RISES strongly toward ~0.26 this step
  → After many steps: fbeak ≈ 0.5 (uniform, but now USED by classifier)
  → ✓ FEATURE AMPLIFIED & USED
  → FMR actually HELPED bring this feature UP to be heard!
🔑 The Asymmetry That Makes FMR Work:

fsky (Blue Sky) fbeak (Beak Curve)
Pretrained magnitude 0.91 ← LOUD 0.12 ← quiet
Actually useful? ❌ No ✅ Yes
Classifier weight Wclass,i ≈ 0 (ignored) +2.3 (relied upon)
∂LCE/∂fi (CE gradient) ≈ 0 (SILENT) −1.61 (FIGHTS)
∂(−λ·H)/∂fi (FMR gradient) −0.23 (push DOWN) +0.21 (push UP)
NET RESULT −0.22 → SUPPRESSED ✓ −1.40 → AMPLIFIED ✓
💡 The Beautiful Asymmetry: FMR doesn't need to know which features are useful. It blindly pushes ALL features toward uniform. But the CE loss selectively resists only for features the classifier actually uses (Wclass,i ≠ 0). Irrelevant features have no champion — they fall to FMR alone. Useful features have CE as their champion — they survive. The classifier is the filter.
Section 05B

How Exactly Do Weights Become Zero? — The Physics of Irrelevance

A natural question: "What actively sets Wsky to zero? Is it ReLU? Dropout? Some special mechanism?"

The answer: none of the above. Weights decay to zero because nothing fights to keep them alive. The mechanism is standard L2 Weight Decay — used in virtually every neural network training setup.

Ltotal = LCE − λ·H + λW·Σ W²

             ↑ Weight Decay term
             Always pulls ALL weights toward zero (like friction)
🔑 Key Insight: Weight decay doesn't know which weights are useful. It pulls EVERY weight toward zero, all the time. Only weights that receive consistent, strong gradients from the CE loss can resist this pull. Irrelevant features get no CE gradient → nothing to fight decay → W drifts to zero.
🔴 fsky (Blue Sky): Gradients CANCEL → W → 0
Batch 1 — Indigo Bunting under blue sky:
  ∂LCE/∂Wsky = (0.5−1.0) × 0.91 = −0.455
  → pushes W DOWN

Batch 2 — Lazuli Bunting under blue sky:
  ∂LCE/∂Wsky = (0.5−0.0) × 0.89 = +0.445
  → pushes W UP

Average gradient ≈ 0.0 ← CANCELS OUT!

But weight decay is ALWAYS running:
  ∂(λW·W²)/∂W = 2·λW·W (always toward zero)

NET: Wsky → 0   ✓ Nothing resists decay
🟢 fbeak (Beak): Gradients CONSISTENT → W SURVIVES
Batch 1 — Indigo Bunting (thick beak, f=0.65):
  ∂LCE/∂Wbeak = (0.3−1.0) × 0.65 = −0.455
  → W INCREASES (prediction was too low)

Batch 2 — Lazuli Bunting (thin beak, f=0.22):
  ∂LCE/∂Wbeak = (0.8−0.0) × 0.22 = +0.176
  → W decreases slightly (thin beak = less Indigo)

Average gradient is CONSISTENTLY negative
  → pushes W in the SAME direction every batch

Gradient signal > Weight decay → W grows

NET: Wbeak → +2.3   ✓ Signal overcomes decay
💡 The Beautiful Simplicity: No special mechanism is needed. The asymmetry emerges naturally from the data:

Component Effect on fsky Effect on fbeak
Feature values across classes Same (≈0.9 for all) Different (0.65 vs 0.22)
CE gradient direction Random (cancels) Consistent (survives)
Weight decay Pulls → 0 (unopposed) Pulls → 0 (opposed by CE)
Final W → 0 → +2.3

It's not ReLU. It's not dropout. It's just weight decay + the absence of a consistent signal. Like a boat with no engine — the current (weight decay) slowly pulls it to shore (zero). Only boats with engines (consistent CE gradients) stay out at sea.

Section 06

Real Life: When Are Features Loud vs Quiet?

🔊 LOUD Features (pretrained bias)
  • Blue sky detector → 0.91 — Birds are often photographed against sky in ImageNet
  • Green foliage → 0.88 — Animals on grass in ImageNet
  • Asphalt/road texture → 0.85 — Cars on roads in ImageNet
  • Center-of-frame bias → 0.79 — Objects centered in ImageNet photos
🔈 QUIET Features (what actually matters)
  • Beak curvature → 0.12 — ImageNet only needed "has beak = bird"
  • Feather tip pattern → 0.08 — Never needed at ImageNet granularity
  • Wing bar width → 0.05 — "Has wing = flying thing" was enough
  • Eye ring shape → 0.03 — Way too fine-grained for ImageNet
⚠️ Can FMR accidentally suppress a genuinely useful loud feature? In theory, yes. In practice, CE loss protects it — if the classifier needs that feature, Wclass,i will be large, CE gradients will push back, and the feature survives. The paper's evidence: FMR on randomly initialized models (no pretrained bias) gives only +0.9% gain vs +10.4% on pretrained models — confirming FMR specifically fixes pretraining-induced bias.
Section 07

Dynamic λ: Why the Regularization Fades

Using a fixed λ would either over-regularize (never let features settle) or under-regularize (not enough push early on). The dynamic formula solves this elegantly:

λ = (Hmax − H) / (Hmax − Hinit)
🔴 Early Training (H ≈ Hinit)

λ ≈ 1.0 — features are very biased, numerator is large → STRONG push toward uniformity

🟢 Late Training (H ≈ Hmax)

λ ≈ 0.01 — features are nearly uniform, numerator is tiny → FMR gracefully exits, letting CE loss finish the job undisturbed

🧠 Intuition: FMR is like training wheels. Strong when you need them (early, biased), then automatically falling away when you don't (late, uniform). The classifier gets the final say.
Section 08

Pre-training vs Fine-tuning: Different Images Entirely

The ResNet-50 backbone was pretrained on ImageNet (1.2M images, 1,000 general classes like "bird", "car", "chair"). It has never seen a CUB200 image. The CUB200 dataset has 6,000 images of 200 bird species — completely different from ImageNet's single "bird" category. FMR corrects the biases the pretrained model brought from its ImageNet training.

Section 10

🔗 Applying FMR to Your Vision-Language Fine-Tuning Work

You're doing Vision-Language fine-tuning with Q&A pairs — images + questions → answers. Your pipeline uses a pretrained vision encoder feeding into an LLM/transformer. This is exactly where FMR helps.

🎯 The Connection: Your vision encoder (ResNet/ViT/CNN) was pretrained on ImageNet or COCO — general images. When you fine-tune it on your specific Q&A dataset with limited examples, the pretrained feature magnitude bias kicks in. Loud-but-irrelevant features (background textures, sky, grass) can dominate, causing the LLM to answer based on spurious visual patterns rather than the actual subject of the question.
⚠️ Do Q&A Pairs Automatically Create Domain Shift?

Not automatically. There are two different kinds of shift — and Q&A pairs always create the second one:

1️⃣ Visual Domain Shift (maybe, maybe not)

Your images look different from ImageNet images.

✅ YES if your images are: medical X-rays, satellite imagery, microscope photos, industrial parts, specific product shots
❌ NO if your images are: everyday photos of birds, cars, people, scenes — same distribution as ImageNet
FMR paper: ImageNet → CUB200 = YES (visual domain shift)

2️⃣ Task-Induced Feature Shift (ALWAYS present with Q&A)

Your task needs different features than ImageNet classification.

✅ ALWAYS because: ImageNet asks "what object?" → emphasizes generic shape/texture. Your Q&A asks "what color is the beak?" → needs fine-grained detail features that ImageNet left QUIET.
Even if your photos are from the same distribution as ImageNet, the features you NEED are different. That's task shift — and FMR fixes it.

🔑 Key Insight:

What ImageNet Learned What Your Q&A Task Needs
"Has beak = bird" → f_beak_shape: 0.12 (quiet) "What color is the beak?" → needs beak_color: should be LOUD
"Has wheels = vehicle" → f_wheel: 0.15 (quiet) "How many wheels visible?" → needs wheel_count: should be LOUD
"Green texture = outdoors" → f_foliage: 0.91 (LOUD) "Is the bird in a tree?" → f_foliage is IRRELEVANT (bird could be anywhere)
"Blue pixels = sky" → f_sky: 0.87 (LOUD) "What species?" → f_sky is USELESS (all birds under blue sky)

Bottom line: Even if your images look exactly like ImageNet photos, your Q&A task asks different questions — so different features matter. FMR equalizes all features, letting your Q&A loss decide which ones are actually useful, rather than letting ImageNet's biases dictate which features dominate.
❌ WITHOUT FMR — What Can Go Wrong
  • Q: "What color is the bird's beak?"
    Model sees loud "green foliage" feature (0.91) → distracted by background → answers based on surrounding vegetation instead of the beak
  • Q: "How many cars in the image?"
    Model latches onto "blue sky" detector (0.87) → misses small distant cars because sky feature dominates
  • Limited Q&A pairs → model memorizes spurious correlations ("all bird photos with blue sky = Indigo Bunting") instead of learning actual visual concepts
✅ WITH FMR — During Fine-Tuning
  • Feature magnitudes equalized → quiet but crucial features (object shape, color, texture details) get equal attention as loud background detectors
  • CE loss protects answer-relevant features — if "beak curvature" helps answer questions correctly, its classifier weight stays large
  • Dynamic λ auto-decays — strong regularization early when bias is worst, fades as the model adapts to your domain
  • Better generalization — model answers based on the actual visual content, not pretrained biases

It's one extra line in your loss function, zero architectural changes, and the dynamic λ means no hyperparameter tuning. Given you're working with limited annotated Q&A data, this is exactly the low-data regime where FMR shows its biggest gains (+10.4% on CUB200 at 15% data).
⏱️ FMR Is Training-Only — But the Behavior Change Sticks

A common question: "Does FMR run during inference? Does it slow down predictions?"

No. FMR only runs during training. But the backbone permanently learns to produce more balanced features.

🏋️ DURING TRAINING (FMR is ACTIVE)
Image → Backbone → f
                 │
                 ├─ Classifier → L_CE
                 └─ FMR: −λ·H(softmax(f))
                     "Equalize those magnitudes!"

Backbone weights get updated by both CE and FMR gradients.
FMR pushes backbone to suppress loud features, amplify quiet ones.
🚀 DURING INFERENCE (FMR is GONE)
Image → Backbone → f → Classifier → Prediction
                 │
                 └─ f is NOW balanced
                     (backbone learned this)

Zero overhead. No entropy calculation.
No λ. No regularization. Same speed.
Same number of parameters.
But the features are balanced — permanently.
🎯 Analogy — Training Wheels on a Bicycle:
  • During training: The training wheels (FMR) force you to balance equally on both sides
  • After training: The wheels come off, but you've learned to balance — your muscle memory (backbone weights) was shaped by them
  • You don't need them anymore because your behavior permanently changed

Same principle as Dropout: Dropout randomly disables neurons during training → network builds redundancy → at inference, dropout is OFF but the network's weights were shaped by it. FMR equalizes features during training → backbone produces balanced features → at inference, FMR is OFF but the backbone's weights were shaped by it.
🔬 How the Backbone Actually Changes — NOT Averaging, Reweighting

A deeper question: "Are the new f values an average of pretrained and new training images? Or does something else happen?"

Neither. The backbone's convolutional filters are physically reweighted. It's not averaging — it's recalibrating which visual patterns get amplified vs suppressed.

FMR gradient flows backward through the ENTIRE backbone:

∂L_FMR/∂(conv_filter_sky) = +0.03 → "Sky filter: you're too loud. Turn DOWN."
∂L_FMR/∂(conv_filter_beak) = −0.02 → "Beak filter: you're too quiet. Turn UP."
∂L_FMR/∂(conv_filter_grass)= +0.02 → "Grass filter: you too. Dial it back."

After SGD update:
sky_filter_weight ← sky_filter_weight − lr × (+0.03) DECREASES
beak_filter_weight ← beak_filter_weight − lr × (−0.02) INCREASES
grass_filter_weight ← grass_filter_weight − lr × (+0.02) DECREASES
Image f_sky (Before FMR) f_sky (After FMR) f_beak (Before) f_beak (After)
Training: Indigo Bunting #1 0.91 0.52 0.12 0.49
Training: Lazuli Bunting #1 0.89 0.50 0.08 0.46
NEW: Unseen Test Image 0.92 0.51 0.10 0.48
🔑 The key distinction:

❌ Wrong Model ✅ Correct Model
"The f values are averaged between pretrained and new images" "The backbone's filters are reweighted" — sky detector gets muted, beak detector gets amplified
"Only training images get balanced features" "ALL images get balanced features" — even images the model has never seen
"It's like mixing old and new knowledge" "It's like recalibrating a microphone array" — the sky mic gets muted, the beak mic gets amplified, for every recording going forward

Every image — old training, new training, unseen test — flows through the SAME updated backbone. The backbone's conv filters don't remember individual images. They learn which visual patterns to amplify and which to suppress, and apply that universally.

You're fine-tuning a vision-language model (LLaVA, GPT-V, etc.) using Alpaca-format Q&A pairs on bird photos. You have 200 labeled examples. Let's compare what happens with and without FMR:

FMR vs ASIF — Side-by-Side Paper Comparison

Both papers by Avraham Chapman & Lingqiao Liu · The University of Adelaide
Overview

Two Papers, One Philosophy: Remove Unwanted Bias from Feature Representations

Both papers share a common author and a common goal — but attack different enemies using different weapons. FMR fights pretrained feature magnitude bias. ASIF fights instance memorization. Together they cover the two biggest problems in low-data fine-tuning.

Acronym FMR — Feature Magnitude Regularization ASIF — Adversarial Suppression of Identity Features
Venue Conference paper (CVPR-style, 8 pages) DICTA 2022 (IEEE Digital Image Computing)
The Enemy Feature Magnitude Bias — pretrained models produce features where some dimensions are naturally much larger than others, regardless of relevance Instance Memorization — large networks memorize unique patterns of individual training samples instead of learning class-level patterns
How the Enemy Hurts Irrelevant but loud features (background, sky) dominate training. With small data, classifier latches onto these → overfitting Network "cheats" by remembering exactly which sample is which. Works perfectly on training data, fails on new data → poor generalization
Core Fix Force all feature dimensions to be equally prominent — no single feature shouts louder than others Force the network to forget which specific training sample it's looking at — only allow features shared across a class

🔗 Common Philosophy: Both papers are by the same first author (Avraham Chapman) and share a deep insight: neural networks have unwanted biases that hurt generalization when data is scarce. FMR attacks bias from pretraining (features are unevenly prominent). ASIF attacks bias from overparameterization (networks memorize instances). Both use automatic, dynamic weighting so no manual hyperparameter tuning is needed. If you're doing low-data fine-tuning, use both — FMR for the vision encoder, ASIF for the classifier head.
